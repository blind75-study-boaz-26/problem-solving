## 1. Valid Anagram

**[문제 링크](https://leetcode.com/problems/valid-anagram/)** · `Easy` · Python · `자력해결`

**입출력**
- 영어 소문자로만 이루어진 문자열 `s`, `t`가 주어진다. (`1 <= s.length, t.length <= 5 * 10^4`)
- `t`가 `s`의 글자를 재배열해서 만들 수 있는 애너그램이면 `True`, 아니면 `False`를 반환한다.

**접근**
1. 브루트포스: 두 문자열을 정렬한 뒤 같은지 비교한다.
2. 한계: 정렬 때문에 시간 복잡도가 `O(N log N)`이 된다.
3. 최종: 길이가 다르면 바로 `False`를 반환하고, 같으면 `a`~`z` 26칸 리스트에 각 문자열의 알파벳 등장 횟수를 세어 두 리스트를 비교한다.

**선택 근거**
입력이 소문자 26개로 제한되어 있으므로, 해시맵 대신 고정 크기 리스트를 쓰면 `ord(c) - ord('a')`로 바로 인덱싱할 수 있고 추가 공간도 상수로 유지된다.

**복잡도**
- 시간: `O(N)` — `s`와 `t`를 각각 한 번씩 순회한다.
- 공간: `O(1)` — 입력 크기와 무관하게 26칸 리스트 2개만 사용한다.

**엣지 케이스**
- [ ] 두 문자열의 길이가 다른 경우: 카운팅 없이 바로 `False`를 반환한다.
- [ ] 같은 글자가 여러 번 나오는 경우 (`"aacc"` vs `"ccac"`): 글자 종류뿐 아니라 개수까지 비교하므로 `False`를 반환한다.
- [ ] 제약 조건 검사 분기: 문제에서 보장하는 조건이라 생략해도 되고, 제거하면 중첩 `if`가 줄어 코드가 더 간결해진다.

**코드**

```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        # 제약 조건 확인 (문제에서 보장하므로 사실 생략 가능)
        # 주의: 파이썬에서 ^는 XOR, 거듭제곱은 **
        if(len(t) <= 5 * (10**4) and 1 <= len(s)):
            # 길이가 다르면 애너그램일 수 없음
            if(len(s)==len(t)):
                # s의 알파벳별 등장 횟수 (인덱스 0~25 = 'a'~'z')
                count_s = [0] * 26
                for c in s:
                    # ord(c) - ord('a'): 글자를 0~25 인덱스로 변환 ('a'→0, 'z'→25)
                    count_s[ord(c)-ord('a')]+=1
                # t의 알파벳별 등장 횟수
                count_t = [0] * 26
                for b in t:
                    count_t[ord(b)-ord('a')]+=1
                # 두 리스트의 모든 칸 값이 같으면 = 모든 글자 개수가 같으면 애너그램
                if(count_s==count_t):
                    return True
                else:
                    return False
            else:
                return False
        else:
            return False
```

**다시 볼 때의 트리거**
> 문자 구성이 같은지 비교할 때는 정렬 대신 알파벳 개수를 세서 비교한다.

<details><summary>선택 항목</summary>

- **소요 시간 / 막힌 지점:** 제약 조건을 코드로 옮기면서 파이썬에서 `^`가 거듭제곱이 아니라 XOR라는 점을 확인했다.
- **복습 필요:** [ ] 유니코드 문자가 들어오는 경우(follow-up)에는 26칸 리스트 대신 해시맵을 사용해야 한다.

</details>

## 2. Product of Array Except Self

**[문제 링크](https://leetcode.com/problems/product-of-array-except-self/)** · `Medium` · Python · `자력해결`

**입출력**
- 정수 배열 `nums`가 주어진다. 모든 prefix/suffix 곱은 32비트 정수 범위 안에 있음이 보장된다.
- `answer[i]`가 `nums[i]`를 제외한 나머지 원소의 곱인 배열을 반환한다. 나눗셈을 쓰지 않고 `O(N)`에 풀어야 한다.

**접근**
1. 브루트포스: 각 `i`마다 자기 자신을 제외한 모든 원소를 곱한다.
2. 한계: 중첩 반복문이 필요해 `O(N^2)`이고, 전체 곱을 나누는 방식은 나눗셈 금지 조건과 `0` 처리 문제가 있다.
3. 최종: `answer[i] = (i 왼쪽 원소들의 곱) × (i 오른쪽 원소들의 곱)`으로 나눈다. 왼→오 순회로 왼쪽 누적 곱을 `answer`에 저장하고, 오→왼 순회로 오른쪽 누적 곱을 곱해 완성한다.

**선택 근거**
"자기 자신 제외"는 왼쪽 구간과 오른쪽 구간의 곱으로 분리할 수 있다. 누적 곱을 변수 `left`, `right` 하나씩으로만 유지하면 prefix/suffix 배열을 따로 만들지 않아도 된다.

**복잡도**
- 시간: `O(N)` — 배열을 왼→오, 오→왼 두 번 순회한다.
- 공간: `O(1)` — 결과 배열 `answer`를 제외하면 `left`, `right` 변수만 추가로 사용한다.

**엣지 케이스**
- [ ] `0`이 하나 포함된 경우: 나눗셈을 쓰지 않으므로 `0`의 위치만 나머지 곱을 갖고, 다른 칸은 `0`이 된다.
- [ ] `0`이 두 개 이상인 경우: 모든 칸이 `0`이 된다.
- [ ] 음수가 포함된 경우: 곱셈만 사용하므로 부호가 자연스럽게 반영된다.

**코드**

```python
class Solution:
    def productExceptSelf(self, nums: list[int]) -> list[int]:
        n = len(nums)
        answer = [1] * n

        # 1단계: 왼쪽 → 오른쪽, answer[i]에 i 왼쪽 원소들의 곱 저장
        left = 1                      # 지금까지의 왼쪽 누적 곱
        for i in range(n):
            answer[i] = left          # 자기 자신은 아직 안 곱한 상태로 저장
            left *= nums[i]           # 다음 칸을 위해 자기 자신을 누적

        # 2단계: 오른쪽 → 왼쪽, answer[i]에 i 오른쪽 원소들의 곱을 곱함
        right = 1                     # 지금까지의 오른쪽 누적 곱
        for i in range(n - 1, -1, -1):  # n-1부터 0까지 거꾸로
            answer[i] *= right        # 왼쪽 곱 × 오른쪽 곱 완성
            right *= nums[i]          # 다음 칸을 위해 자기 자신을 누적

        return answer
```

**다시 볼 때의 트리거**
> "자기 자신 제외" 연산은 왼쪽 누적값과 오른쪽 누적값의 조합으로 분리한다.
