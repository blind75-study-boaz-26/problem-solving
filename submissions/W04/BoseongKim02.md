## 338. Counting Bits

**[문제 링크](https://leetcode.com/problems/counting-bits/)** · `Easy` · Python · `해설봄`

**입출력**
- 입력: 정수 n (0~10^5). 출력: 0부터 n까지 각 수의 이진수 표현에서 1의 개수를 담은 길이 n+1 배열. 내장 popcount 함수 사용 금지

**접근**
1. 브루트포스: 0부터 n까지 각 수를 이진수로 바꿔 1의 개수를 매번 처음부터 셈 (O(n log n))
2. 한계: 문제에서 O(n)을 요구함. 숫자마다 비트를 새로 세는 중복 계산을 없애야 함
3. 최종: i >> 1은 i에서 마지막 비트만 뗀 수이므로, ans[i] = ans[i >> 1] + (i & 1) 점화식으로 이미 구한 작은 답을 재사용

**선택 근거**
- i >> 1은 항상 i보다 작아서, 0부터 순서대로 채우면 필요한 값이 이미 배열에 있음. 배열 인덱스로 O(1)에 조회 가능하므로 결과 배열 자체를 DP 테이블로 사용

**복잡도**
- 시간: `O(n)` — n번 반복하며 매번 시프트·AND·덧셈·배열 조회만 수행(각 O(1))
- 공간: `O(n)` — 결과 배열(출력) 외 추가 공간 없음

**엣지 케이스**
- [ ] n = 0 → range(1, 1)이 비어 루프가 돌지 않고, 초기화된 [0]을 그대로 반환
- [ ] 2의 거듭제곱 (예: 4 = 100) → ans[2] + (4 & 1) = 1 + 0 = 1. 짝수는 >>1 해도 버려지는 비트가 0이라 1의 개수가 그대로 유지됨

**코드**

```python
class Solution(object):
    def countBits(self, n):
        ans = [0] * (n + 1)
        for i in range(1, n + 1):
            ans[i] = ans[i >> 1] + (i & 1)
        return ans
```

**다시 볼 때의 트리거**
> 0~n의 비트 개수 → ans[i] = ans[i >> 1] + (i & 1). 홀수는 >>1에서 1을 하나 잃고, 짝수는 잃지 않는다.

<details><summary>선택 항목</summary>

- **소요 시간 / 막힌 지점:** i & 1 연산의 의미와, 홀짝에 따른 >>1 전후 1의 개수 변화가 점화식으로 이어지는 구조를 이해하는 데 시간이 걸렸다. / 약 30분

## 268. Missing Number

**[문제 링크](https://leetcode.com/problems/missing-number/)** · `Easy` · Python · `해설봄`

**입출력**
- 입력: 서로 다른 n개의 정수 배열 nums (n은 1~10^4, 각 값은 0~n 범위). 출력: 0~n 범위에서 배열에 빠진 유일한 수

**접근**
1. 브루트포스: 0부터 n까지 각 수가 nums에 있는지 `in`으로 확인 (리스트 탐색이 O(n)이라 전체 O(n²))
2. 한계: 문제에서 O(n)을 요구함. 매번 배열 전체를 다시 훑는 탐색을 없애야 함
3. 최종: 0~n의 합은 공식 n(n+1)/2로 O(1)에 구할 수 있으므로, 이 값에서 실제 배열 합을 빼면 빠진 수가 나옴

**선택 근거**
- 해시셋으로도 O(n)이 가능하지만 O(n) 추가 공간이 필요함. 합 공식은 별도 자료구조 없이 변수 몇 개로 끝나 공간 O(1)

**복잡도**
- 시간: `O(n)` — sum(nums)로 배열을 한 번 순회, 공식 계산은 O(1)
- 공간: `O(1)` — 변수 몇 개만 사용

**엣지 케이스**
- [ ] 빠진 수가 n인 경우 (예: [0,1] → 2) → 배열 길이로 n을 구하므로 범위 끝까지 포함한 합(3)에서 실제 합(1)을 빼 2를 정상 반환
- [ ] 빠진 수가 0인 경우 (예: [1] → 0) → 기대 합 1에서 실제 합 1을 빼 0 반환

**코드**

```python
class Solution(object):
    def missingNumber(self, nums):
        n = len(nums)
        expected_sum = n * (n + 1) // 2
        actual_sum = sum(nums)
        return expected_sum - actual_sum
```

**다시 볼 때의 트리거**
> 0~n 중 빠진 하나 → (있어야 할 합 n(n+1)/2) − (실제 합).

<details><summary>선택 항목</summary>

- **소요 시간 / 막힌 지점:** 브루트포스가 왜 O(n²)인지(리스트의 in 연산이 O(n))를 이해하고, 합 공식으로 O(1) 공간 풀이가 된다는 걸 해설로 확인했다. / 약 15분

</details>

## 371. Sum of Two Integers

**[문제 링크](https://leetcode.com/problems/sum-of-two-integers/)** · `Medium` · Python · `해설봄`

**입출력**
- 입력: 정수 a, b (각각 -1000~1000, 음수 포함). 출력: + 와 − 연산자를 쓰지 않고 구한 a + b

**접근**
1. 브루트포스: 한쪽 수만큼 1씩 증가시키는 방식은 결국 +/−를 써야 하거나 음수 처리가 불가능함
2. 한계: 산술 연산자 없이 덧셈을 표현할 다른 방법이 필요함
3. 최종: XOR로 자리올림 없는 합을, (AND << 1)로 자리올림을 구하고, 자리올림이 0이 될 때까지 반복

**선택 근거**
- 이진 덧셈에서 XOR은 자리올림을 무시한 합과 같고, AND는 두 비트가 모두 1인(자리올림이 생기는) 위치를 찾음. 파이썬 정수는 비트 수 제한이 없어 0xFFFFFFFF 마스크로 32비트로 잘라야 음수에서 무한 루프를 막을 수 있음

**복잡도**
- 시간: `O(1)` — 32비트로 고정되어 반복 횟수가 최대 32회 정도
- 공간: `O(1)` — 변수 몇 개만 사용

**엣지 케이스**
- [ ] 음수 + 양수 (예: a = -1, b = 1 → 0) → 마스크 없이는 자리올림이 끝없이 왼쪽으로 이동해 무한 루프. 매 반복 & mask로 32비트를 넘는 비트를 버려 carry가 0이 되며 종료
- [ ] 결과가 음수 (예: a = -2, b = -3 → -5) → 마스크 결과가 0x7FFFFFFF보다 크면 32비트 음수 패턴이므로 ~(a ^ mask)로 파이썬 음수로 변환

**코드**

```python
class Solution(object):
    def getSum(self, a, b):
        mask = 0xFFFFFFFF

        while b != 0:
            carry = (a & b) << 1
            a = (a ^ b) & mask
            b = carry & mask

        if a > 0x7FFFFFFF:
            a = ~(a ^ mask)

        return a
```

**다시 볼 때의 트리거**
> +/− 없이 덧셈 → XOR은 합, (AND << 1)은 자리올림, carry가 0일 때까지 반복. 파이썬은 32비트 마스크와 음수 복원 필수.

<details><summary>선택 항목</summary>

- **소요 시간 / 막힌 지점:** XOR/AND로 덧셈이 되는 원리는 이해했지만, 파이썬의 무한 비트 정수 때문에 필요한 마스크와 음수 변환 처리는 스스로 떠올리지 못했다. / 약 25분
