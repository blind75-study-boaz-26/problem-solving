## 1. Two Sum

**[문제 링크](https://leetcode.com/problems/two-sum/)** · `Easy` · Python · `힌트봄`
<!-- 결과 태그: 자력해결 / 힌트봄 / 해설봄 — 솔직하게. 복습 리스트의 근거가 됩니다. -->

**입출력**
<!-- 입력 제약(길이·값 범위·중복·음수 여부)과 출력 형태. 1~2줄 -->
-입력: 정수 배열 nums (길이 2~10^4, 값 범위 -10^9~10^9, 중복 값 허용), 정수 target (범위 -10^9~10^9)
출력: 합이 target이 되는 두 인덱스의 배열 (정답은 항상 정확히 하나 존재, 순서 무관)

**접근**
<!-- 브루트포스 → 왜 부족한가 → 최종 아이디어 한 문장. 3줄 이내 -->
1. 브루트포스: 모든 (i,j) 쌍을 이중 루프를 통해 비교하여 합이 target이 되는지 확인한다. O(n^2)
2. 한계: n이 10^4까지 가는데 값의 범위가 크기 때문에 더 빠른 방법이 필요하다.
3. 최종: 배열을 한 번 순회하며 지금까지 본 값을 해시 맵에 저장, 각 원소에서 필요한 짝이 이미 해시 맵에 있는지 즉시 확인한다.

**선택 근거**
<!-- 왜 이 자료구조/알고리즘인가. 1~2줄 -->
-해시 맵은 key를 통해 값을 O(1)에 조회 가능해서, 짝이 이미 나왔는지를 순회 한 번으로 확인 가능하다.

**복잡도**
- 시간: `O(n)` — 배열을 한 번만 순회, 해시 맵 조회 O(1)
- 공간: `O(n)` — 최악의 경우에 배열 전체가 해시 맵에 저장됨

**엣지 케이스** (최소 2개, 처리 방법까지)
- [3,3] : 같은 값이 배열에 두 번 나오는 경우. -> 확인을 먼저 한 후에 저장을 하기 때문에 같은 인덱스를 자기 자신과 짝짓는 오류를 범하지 않는다.
- [5, 3, 8, 2, 7], target = 9 : 정답이 배열의 마지막 두 원소인 경우 -> 순회 끝까지 가야 찾아지므로 중간에 조기 종료하지 않고 끝까지 도는 구조로 처리된다.

**코드**

```python
# LeetCode에서 Accepted 받은 코드를 그대로. 다듬지 않기.

class Solution(object):
    def twoSum(self, nums, target):
        seen = {}
        for i, num in enumerate(nums) :
            complement = target - num
            if complement in seen :
                return [seen[complement], i]
            seen[num] = i

        return []

```

## 2. Best Time to Buy and Sell Stock

**[문제 링크](https://leetcode.com/problems/best-time-to-buy-and-sell-stock/)** · `난이도` : Easy · Python · `힌트봄`

**입출력**
- 입력 - 정수 배열 prices(i번째 값 = i번째 날의 주가)
출력 - 한 번 사고 팔았을 때 낼 수 있는 최대의 수익. 만약 없다면 0

**접근**
prices.length가 <=10^5 이고, 10^8 내로 들어와야 하므로 O(n^2) 방식인 bruteforce는
적합하지 않은 방식이라는 것을 생각하였다. 파는 날의 수익은 그 이전 구간의 최솟값에서 샀을 때 최대이므로, 배열을 한 번만 순회하며 지금까지의 최솟값만 갱신하면 이중 루프를 단일 루프로 줄일 수 있음.

**선택 근거**
- 값들 간 관계를 재구성할 필요가 없고, 순차 스캔으로 충분하므로 정렬 또는 해시 맵이 필요하지 않았기 때문에 변수 2개(min_price, max_profit)만 사용하였다.

**복잡도**
- 시간: `O(n)` — 배열을 한 번만 순회한다.
- 공간: `O(1)` — 추가 자료구조 활용 없이 변수 2개만 사용하였다.

**엣지 케이스**
- 가격이 계속 하락하는 경우 : [7, 6, 5, 3, 2] -> max_profit = 0을 반환한다.
- 배열의 길이가 1인 경우 : [4] -> 루프가 돌지 않으므로 max_profit = 0을 그대로 반환한다.

**코드**

```python
class Solution(object):
    def maxProfit(self, prices):
        min_price=prices[0]
        max_profit = 0
        for i in range(1, len(prices)):
            if prices[i] < min_price:
                min_price = prices[i]
            if prices[i] - min_price > max_profit:
                max_profit = prices[i] - min_price
        return max_profit

```

**다시 볼 때의 트리거**
> 가격 배열에서의 최대 수익 -> 지금까지의 최솟값을 추적하며 한 번의 순회로 최대 차이 갱신.
